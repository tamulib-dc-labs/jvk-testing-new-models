# Whisper Transcript Reviewer

A web application for reviewing VTT files and Whisper / Whisper X JSON transcripts with word-level confidence scoring.

## Reviewing a pipeline run

The site is organised around three views of the selected recording, plus a
switcher for choosing *which* pipeline run you are looking at.

- **Pipeline run switcher** (header) — lists every branch of the repository
  named in `site.repository`. Picking one loads that branch's
  `public/config.json` straight from `raw.githubusercontent.com`, so an
  automation branch can be reviewed before its PR is merged. Branches that have
  an open PR are labelled with the PR number, and the link under the dropdown
  jumps to that PR. "This build" falls back to the `config.json` bundled with
  the deployed site, and "Other branch…" accepts any branch name by hand.
- **Transcript** — the audio player and the word-confidence transcript, with a
  strip under it showing the current word and its score as the audio plays.
- **VTT** — the cue list parsed from the `.vtt`, with per-cue timestamps you can
  click to seek, speaker chips, a text search, a speaker filter, follow-the-audio
  highlighting, and a toggle for the raw file.
- **JSON** — the run's metadata at a glance (ASR model, language, speakers,
  segment/word counts, alignment success rate, audio length, processing time and
  realtime factor), the word score buckets, the spread of word confidences
  against the active thresholds, per-stage timings, and the raw payload.

Each of JSON and VTT has **Open** (raw URL in a new tab), **Download** and
**Copy link** buttons. Recordings whose `url` or `vtt` is blank in `config.json`
are shown with a struck-through badge rather than a broken link.

The **Scoring** panel still switches between the thresholds carried in the JSON
(`word_score_buckets`) and your own static ones.

## Using This Template

This repository is a GitHub template. To create your own instance:

1. Click **"Use this template"** > **"Create a new repository"** on GitHub
2. Edit `config.yml` to customize your site (you can do this directly in GitHub's web interface):

```yaml
site:
  title: "My Transcript Reviewer"
  subtitle: "Your custom subtitle here"
  footer_text: "Your Footer Text"
  theme: "synthwave"  # See themes section below
```

3. Add your media files to `public/config.json` (see format below)

4. Enable GitHub Pages:
   - Go to **Settings** > **Pages**
   - Under **Source**, select **GitHub Actions**

5. Push your changes - the site will automatically build and deploy!

Your site will be available at: `https://YOUR-USERNAME.github.io/YOUR-REPO-NAME/`

## Configuration

### Site Configuration (config.yml)

Edit `config.yml` to customize your site's appearance:

| Setting | Description | Default |
|---------|-------------|---------|
| `site.title` | Page title and header text | "Whisper Transcript Reviewer" |
| `site.subtitle` | Subtitle below the header | "Review VTTs Generated by Whisper or Whisper X." |
| `site.footer_text` | Footer text | "Whisper JSON Viewer" |
| `site.theme` | DaisyUI theme name | "synthwave" |
| `site.repository` | `owner/name` the branch switcher lists runs from | auto-detected |

`site.repository` is what powers the pipeline-run switcher. The build writes it
to `public/site.json`; if it is left blank the app falls back to
`GITHUB_REPOSITORY` at build time, and then to inferring `owner/repo` from the
GitHub Pages URL. Branch listing uses the unauthenticated GitHub API, so it is
rate-limited per IP and cached for ten minutes; if it is unavailable the site
still works against the bundled `config.json`.

Optional build settings:

```yaml
build:
  base_path: "/custom-path/"  # Override auto-detected path
```

The base path is automatically detected from your repository name, so you typically don't need to set this.

### Media Files (config.json)

Add your transcript files to `public/config.json`. Each entry should have:

```json
[
  {
    "audio": "https://example.com/media/audio.m3u8",
    "url": "https://example.com/transcripts/transcript.json",
    "vtt": "https://example.com/vtts/subtitle.vtt",
    "name": "display-name"
  }
]
```

| Field | Required | Description |
|-------|----------|-------------|
| `audio` | Yes | URL to audio/video stream (M3U8, MP4, etc.) |
| `url` | Yes | URL to Whisper X JSON transcript |
| `vtt` | No | URL to VTT subtitle file |
| `name` | Yes | Display name in the dropdown selector |

See `public/config.example.json` for a sample.

### Transcript JSON Format

The transcript JSON files can include optional word-level data with confidence scores:

```json
{
  "word_score_buckets": {
    "Good": 0.85,
    "Neutral": 0.65,
    "Bad": 0.25
  },
  "segments": [...]
}
```

This is useful to add to your pipeline when you have items with particularly bad confidence scores.

If `word_score_buckets` is not included, defaults will be used instead.

Newer pipeline runs also emit provenance alongside the segments, all of it
optional and all of it surfaced on the **JSON** tab:

```json
{
  "asr_model": "nvidia/parakeet-tdt-0.6b-v3",
  "language": "en",
  "speakers": ["S01", "S02"],
  "alignment_stats": { "total_segments": 257, "success_rate": 100.0, "total_words": 3703 },
  "run": {
    "audio_seconds": 1758.8,
    "stage_seconds": { "ingest": 0.7, "models": 614.1, "fuse": 0.01, "reflow": 0.03 }
  }
}
```

Segments and words may carry a `speaker` label, which the VTT view also reads
from `<v S01>` voice spans. Older transcripts without any of these fields render
exactly as before.

## Local Development

```bash
npm install         # Install dependencies
npm run dev         # Start development server
npm run build       # Build for production
npm run preview     # Preview production build locally
```

## Deployment

This project automatically builds and deploys via GitHub Actions when you push to the main branch.

**Important:** You must configure GitHub Pages to deploy from **GitHub Actions** (not from a branch):
1. Go to **Settings** > **Pages**
2. Under **Source**, select **GitHub Actions**

The build process:
1. Reads your `config.yml` settings
2. Updates the HTML with your title, subtitle, theme, and footer
3. Sets the correct base path from your repository name
4. Builds and deploys to GitHub Pages

## Themes

This project uses [DaisyUI](https://daisyui.com/docs/themes/) themes. Available themes include:
- light, dark, cupcake, bumblebee, emerald, corporate
- synthwave, retro, cyberpunk, valentine, halloween, garden
- forest, aqua, lofi, pastel, fantasy, wireframe, black
